# Saber 企业级开发执行与跨模型接力计划

> 版本：1.0（2026-08-25）
> 依据：[企业级本地 CodingAgent IDE 产品与架构方案](./企业级本地CodingAgent-IDE产品与架构方案.md)
> 目标：把总体方案拆成可独立验收、可由不同大模型继续、每段都能提交并推送远程的工程批次。

## 0. 当前事实与执行边界

当前目录不是 Git 仓库，没有配置远程。因此：

- 本文可以完成规划和模板，但当前不能真实 push。
- S00 是所有产品开发之前的硬门：初始化/克隆正式仓库、绑定远程、保护 main、建立 CI。
- 从 S01 开始，每段必须在独立分支完成；测试、交接文件、commit、push、远端 SHA 校验全部成功后才算 Completed。
- 不直接向 main 开发，不 force push，不把 Secret、聊天私密内容或模型隐藏推理写入仓库。

## 1. 总执行原则

### 1.1 聊天不是事实源

开发权威顺序：

1. 远程 Git commit 与签名 tag。
2. 当前分支代码、Schema、迁移、测试和构建产物清单。
3. docs/adr、docs/traceability.yaml、evals 与交接胶囊。
4. Issue/PR 中已确认的决定。
5. 当前聊天，仅作为临时协作界面。

换模型时，新模型必须从仓库恢复，不依赖上一模型的“记忆”。

### 1.2 一段只解决一个可验收目标

每段控制在 2-10 个工作日。若超过：

- 拆成 Sxx-a/Sxx-b；
- 每个子段仍需独立测试和 push；
- 禁止用“完成 80%”标记 Completed。

### 1.3 完成定义

每段必须同时满足：

- 范围内实现完成；
- Acceptance Criteria 有机器证据；
- 新副作用进入 Capability/Policy；
- 单元、集成、契约、安全或故障测试按风险通过；
- 文档、ADR、Schema、traceability 同步；
- HANDOFF.md 与 STATE.yaml 更新；
- 普通 commit 成功；
- feature branch push 成功；
- 远程分支 SHA 与本地 HEAD 一致；
- CI 通过；需要 Review 的段已创建 PR。

## 2. 跨模型继续开发协议

### 2.1 仓库内的 Continuity Pack

S00 建立下列文件，所有模型共用：

~~~text
AGENTS.md
docs/
  architecture/
  adr/
  runbooks/
  traceability.yaml
  execution/
    ROADMAP.md
    STATE.yaml
    HANDOFF.md
    DECISIONS.md
    KNOWN-ISSUES.md
    EVIDENCE.json
evals/
schemas/
.github/
  pull_request_template.md
~~~

各文件职责：

| 文件 | 作用 | 禁止内容 |
|---|---|---|
| AGENTS.md | 所有模型必须遵守的构建、测试、安全和提交规则 | 单次任务进度、Secret |
| STATE.yaml | 当前阶段、分支、commit、状态、下一段、阻塞 | 长篇解释 |
| HANDOFF.md | 上一执行者给下一模型的可读交接 | 隐藏思维链、无证据猜测 |
| EVIDENCE.json | 测试命令、exit code、artifact hash、CI URL | “测试应该通过” |
| DECISIONS.md/ADR | 已接受的设计决定与替代方案 | 临时讨论 |
| KNOWN-ISSUES.md | 已复现问题、影响、规避、owner | 未验证传闻 |
| traceability.yaml | requirement → module → event → test → segment | 无 owner 的 P0 需求 |

### 2.2 模型切换触发条件

满足任一条件就先停止新增代码，执行交接：

- 当前模型额度/上下文可能不足以完成本段验证；
- 需要更强的架构、安全或复杂调试模型；
- 机械批量任务适合更便宜模型；
- 同类失败两次，需要换独立策略；
- 到达预设 checkpoint；
- 用户主动要求换模型或 Provider。

不能可靠读取“剩余额度”时，不等待耗尽；在每个关键里程碑后主动生成可恢复状态。

### 2.3 交接前 12 步

1. 停止扩大范围。
2. 运行 git status，记录未跟踪和已修改文件。
3. 把当前工作归类为 completed、partial、not-started。
4. 运行本段已具备的测试；失败也要保存真实结果。
5. 更新 ADR/Decision，不让决定只留在聊天。
6. 更新 STATE.yaml 的分支、HEAD、Segment、状态和 Next Action。
7. 更新 HANDOFF.md：目标、完成、未完成、验证、风险、下一条命令。
8. 更新 EVIDENCE.json；只记录可重放命令和结果。
9. 检查 Diff 中是否有 Secret、临时大文件和无关改动。
10. 如果本段尚未完成，用 WIP checkpoint commit，不能伪装成完成。
11. 普通 push 当前分支。
12. 用 git ls-remote 验证远端 SHA，向下一模型提供恢复提示。

### 2.4 新模型接手 14 步

1. 确认 repo URL、目标分支、remote 和本地路径。
2. git fetch --prune。
3. 检查远程 branch HEAD 与交接 SHA。
4. 确认工作树干净；不覆盖用户未提交更改。
5. 阅读 AGENTS.md。
6. 阅读 STATE.yaml 和 HANDOFF.md。
7. 阅读当前段关联 ADR、Schema、traceability 和 Issue/PR。
8. 查看 git show 与本段完整 diff。
9. 运行 HANDOFF 指定的快速恢复测试。
10. 验证环境、工具链、数据库迁移和依赖锁指纹。
11. 将上一模型的结论视为待验证摘要，不视为事实。
12. 复述本段 Acceptance、边界和阻塞。
13. 只从 Next Action 继续，不重复已经有证据的工作。
14. 若证据不一致，进入 Reconcile 并更新交接文件。

### 2.5 大模型分工建议

模型名不写死在业务逻辑中，用 profile 映射：

| Profile | 用途 | 质量要求 |
|---|---|---|
| frontier-architect | Schema、信任边界、安全、难调试、最终 Review | 高推理、完整证据 |
| balanced-builder | 常规 Rust/TS/IDE 实现 | 成本和质量平衡 |
| fast-mechanical | codegen、格式化、测试样例、文档同步 | 强 Schema 约束 |
| local-private | 高敏代码检索、初筛、Embedding | 数据不外发 |
| independent-reviewer | 与作者不同模型做回归/安全 Review | 不能复用作者结论 |

当前 OpenAI 官方模型指导建议把模型变更和 Prompt 变更分开，一次只改变一个变量并在代表任务上运行 Eval；本计划同样要求换模型后先保持任务契约不变，再比较质量。OpenAI API 内的同系列多轮可使用 conversation state；跨 Provider/跨产品接力仍以 Continuity Pack 为准。

## 3. Git、提交、推送和 PR 规则

### 3.1 分支

~~~text
main                         # 受保护，可发布基线
segment/S00-repo-bootstrap
segment/S01-constitution
segment/S02-monorepo-ci
...
release/v0.1.0
hotfix/<incident-id>
~~~

每个 Segment 从最新 origin/main 创建。禁止多个模型在同一分支并发写；需要并行时使用不同子分支/worktree，并由 Integrator 合并。

### 3.2 Commit

~~~text
feat(S08): add provider-neutral model contract
fix(S10): prevent untrusted memory promotion
test(S06): add sandbox symlink escape cases
docs(S00): add cross-model handoff protocol
chore(S02): pin toolchain and CI images
~~~

要求：

- commit 只包含当前段相关文件；
- 生成文件与源 Schema 一并提交；
- 迁移不可只提交最终数据库；
- 不使用 --no-verify 绕过钩子；
- WIP commit 必须写明 wip(Sxx)，完成 Gate 前不得合入 main。

### 3.3 每段结束的固定命令序列

命令中的分支名和测试命令按 Segment 替换：

~~~bash
git status --short
git diff --check
<segment lint command>
<segment unit command>
<segment integration/security command>

git add <explicit-paths>
git diff --cached --check
git diff --cached --stat
git commit -m "feat(Sxx): <segment outcome>"
git push -u origin segment/Sxx-<slug>

local_sha=$(git rev-parse HEAD)
remote_sha=$(git ls-remote --heads origin segment/Sxx-<slug> | awk '{print $1}')
test "$local_sha" = "$remote_sha"
~~~

最后一个 test 不通过，Segment 状态只能是 PushFailed/Blocked，不能写 Completed。

### 3.4 PR 与 main

- feature branch push 后创建 PR；
- Required checks 全绿；
- 安全/Schema/Policy/E2EE/Evolution 段需要对应 Code Owner；
- squash/merge 策略由 S00 ADR 决定；
- merge 后验证 origin/main 包含 Segment commit；
- 删除远程分支前确保 tag/PR/commit 可追溯；
- 禁止 force push main，禁止 Agent 自行关闭未解决的安全意见。

### 3.5 Push 失败

按 auth、network、non-fast-forward、branch protection、CI 分级：

1. 保存错误原文到 HANDOFF，不记录 Token。
2. auth 失败不尝试读取或打印凭证。
3. non-fast-forward 先 fetch/rebase 或新分支，不 force。
4. CI 失败回到本段修复并重新 push。
5. 远程不可用时保留本地 commit 和 bundle；恢复后再推，状态不是 Completed。

## 5. 逐段执行计划

## S00：正式仓库、远程与接力骨架

目标：建立后续每段都能安全 push 和换模型接力的基础。

步骤：

1. 决定正式仓库位置：新建远程或克隆已有远程；不要在未知目录直接 git init 后假装已连接。
2. 确认组织/个人 owner、默认分支、可见性、数据分类和许可证。
3. 配置 origin，完成最小 README、.gitignore、LICENSE/NOTICE 决策。
4. 配置 main 保护、Required checks、禁止 force push、Code Owners。
5. 建 AGENTS.md、execution/STATE.yaml、HANDOFF.md、EVIDENCE.json 和 PR 模板。
6. 建 Secret scan、Markdown/schema lint 和最小 CI。
7. 提交 docs 与接力骨架。
8. push segment/S00-repo-bootstrap，验证远程 SHA。
9. 通过 PR 合入 main，再验证 origin/main。

交付：可克隆仓库、远程保护、接力文件、首个 CI、S00 PR。
Gate：另一台临时目录可 clone、读 HANDOFF、运行检查、得到相同 HEAD。
Commit：chore(S00): bootstrap repository and model handoff
注意：当前正阻塞在“没有 Git 仓库和远程 URL”这一前置事实。

## S01：产品宪法、需求追踪与架构决策

步骤：

1. 从 v2.0 总体方案提取 FR/SEC/RES/OPS Requirement ID。
2. 建 traceability.yaml，绑定 owner、module、event、test placeholder、Segment。
3. 建 ADR-001 至 ADR-006：Rust Core、IPC、SQLCipher、Event+Projection、Blob、Schema codegen。
4. 固化八条架构不变量和 E0-E7 进化边界。
5. 建 Threat Model v0 和数据分类。
6. 加 CI 检查 P0 requirement 必须有 owner/test。

Gate：P0 无孤儿需求；信任边界与非目标已签署。
Push：segment/S01-constitution。

## S02：Monorepo、工具链和 CI

步骤：

1. 建 apps、crates、packages、schemas、evals 目录。
2. 锁定 Rust stable、Node LTS、pnpm、codegen、SQL migration 工具。
3. 建格式化、lint、unit、license、dependency、secret scan。
4. 建 macOS/Windows/Linux CI 骨架和缓存。
5. 建开发环境 bootstrap 与 30 分钟新机验收。

Gate：空骨架三平台构建；lockfile/toolchain 可复现。
Push：segment/S02-monorepo-ci。

## S03：领域 Schema 与 Control Protocol

步骤：

1. 定义 Workspace、Goal、Task、Run、Artifact、Decision、Memory、Capability、Incident、EvolutionCandidate。
2. 定义 Event Envelope、ID、版本、因果、敏感性和 Policy 字段。
3. 定义本地 JSON-RPC over Unix Socket/Named Pipe。
4. 从 Schema 生成 Rust/TS 类型。
5. 建 N/N-1、fuzz、frame size、deadline、idempotency 合约测试。

Gate：Rust/TS round-trip；非法状态和未知 method 确定失败。
Push：segment/S03-domain-protocol。

## S04：SQLCipher Event Store 与 Run 状态机

步骤：

1. OS Keychain 获取数据库 Key，禁止 env/argv/log。
2. 建 events、projections、outbox、runs、artifacts、blobs。
3. Event append、projection、outbox 同事务。
4. 实现 Run 状态机和 verified-success 约束。
5. 实现 hash chain、replay、crash-tail repair。
6. kill -9、disk-full、DB-busy 故障注入。

Gate：确认事件不丢；重复 idempotency 不产生第二次副作用。
Push：segment/S04-event-store。

## S05：Capability、Policy 与 Approval

步骤：

1. 冻结 fs/process/network/secret/git/external/self-change vocabulary。
2. 实现 Rust PDP/PEP 和严格合并顺序。
3. 实现 scope、TTL、resource hash 绑定审批。
4. 实现 Decision audit 和 redaction。
5. 建 deny、TOCTOU、过期、故障 fail-closed 测试。

Gate：没有 Policy Decision 的副作用调用为零。
Push：segment/S05-policy。

## S06：Sandbox、Secret Broker 与 Egress

步骤：

1. 建 Sandbox SPI：create/exec/mount/network/kill/snapshot/destroy。
2. 完成 macOS/Linux/Windows feasibility 和最小生产后端。
3. workspace 默认 ro；修改使用 worktree/overlay。
4. Secret 只以 credential_ref 进入 Tool，短期注入并撤销。
5. 网络默认 deny；域名/IP/redirect/DNS/metadata endpoint 控制。
6. 测 path、symlink、process、bind、network、stdout secret。

Gate：已知逃逸和 Secret 外泄为零；后端不可用时只读/fail-closed。
Push：segment/S06-sandbox-secret-egress。

## S07：Tool Broker 与可恢复修改

步骤：

1. 统一 describe/authorize/prepare/execute/verify/compensate。
2. 实现 read/stat/hash/patch/git diff/status/shell/test。
3. 每次副作用先 intent、后 result、再 verification。
4. 所有修改进入 worktree/checkpoint。
5. 外部编辑和 Git fingerprint 变化进入 Reconcile。

Gate：工具不能伪造成功；失败可回滚或明确 non-retriable。
Push：segment/S07-tool-broker。

## S08：ModelProvider、Router 与换模型执行

步骤：

1. 定义 stream/tool/structured output/usage/cancel/error/data-policy SPI。
2. 接 OpenAI-compatible、Anthropic-compatible、Ollama。
3. 建 signed Model Registry 与 capability probe。
4. Router 先按 sensitivity/residency/capability 过滤，再按质量/成本选。
5. Run 固化 provider/model/config/prompt/tool/policy 版本。
6. 同一任务在 frontier/balanced/local profile 做成对 Eval。
7. 实现 model switch checkpoint：停止 Turn、写 Capsule、新模型重新验证后继续。

Gate：换模型不改变 Goal/Task/Run 主数据；不重复已完成副作用；质量回归可发现。
Push：segment/S08-model-provider。

## S09：Context Engine 与 Knowledge Mesh

步骤：

1. 实现 ContextChunk provenance/taint/sensitivity/scope/token cost。
2. 接 FTS5、Tree-sitter/LSP；向量先作为可重建 SPI。
3. 实现 Personal/Workspace/Team/Org/External Knowledge Space。
4. Policy-aware query planner 在检索前过滤。
5. 建 Context Preview/Receipt。

Gate：每个发给模型的片段可解释来源、原因、目的地；越权跨域为零。
Push：segment/S09-context-knowledge。

## S10：Memory Authority

步骤：

1. 实现 Episodic、Curated、Prospective、Review 层。
2. 单一逻辑写者、proposal、expected revision、ledger。
3. 来源分类存结构字段，防来源洗白和 recall loop。
4. 实现 promote/reject/revoke/expire/forget/redact。
5. 实现无模型 Lane 1 和受限 Recall Agent Lane 2。

Gate：并发写不覆盖；untrusted 不自动晋升；precision 达阶段目标。
Push：segment/S10-memory-authority。

## S11：Code-OSS 桌面纵向闭环

步骤：

1. 完成 Code-OSS vs Tauri ADR，主线只保留一个壳。
2. 建 Goal、Conversation、Changes、Runtime、Knowledge 五工作面。
3. 接 Context Preview、Approval、Diff/Test/Review/Apply/Rollback。
4. UI 只走 Control Protocol，不直连 DB/Tool。
5. UI crash/restart 从 cursor 补事件。

Gate：完成一个真实修复任务；UI crash 不终止 Core Run。
Push：segment/S11-desktop-vertical。

## S12：CAX、采集流水线与首批 Importer

步骤：

1. 定义 Manifest/Consent/Raw/Canonical/Derived/Lineage。
2. 实现 import state machine 和 parser version。
3. 原始证据加密保存；派生层可重算。
4. 先接两个官方 Export/结构化来源。
5. 去重、删除影响、撤权、来源污点测试。

Gate：重复导入不重复造 Memory；Derived 可从 Raw 重建。
Push：segment/S12-cax-import。

## S13：Resumption Capsule 与跨 Agent 续接

步骤：

1. 实现候选谱系解析和用户确认。
2. 记录 repo/branch/commit/dirty hash/dependency/policy。
3. Revalidate 生成 unchanged/diverged/missing/unknown。
4. 区分 Native Resume、Canonical Successor、Knowledge Continuation。
5. 接一个支持 resume/fork 的 Agent Driver。

Gate：环境漂移必被显示；后继事件连接原谱系；不宣传隐藏状态无损迁移。
Push：segment/S13-resumption。

## S14：Goal DAG 与 Subagents

步骤：

1. 实现依赖、防环、预算、acceptance、failure propagation。
2. Planner/Implementer/Reviewer 隔离 context/tool/worktree。
3. 子 Agent 使用衰减 Capability token。
4. 结果必须带 artifact/evidence/hash。
5. 单 Agent crash/cost runaway 故障测试。

Gate：文本自述不能使 Task Succeeded；父 Goal 可恢复。
Push：segment/S14-goal-subagents。

## S15：Evolution Workshop

步骤：

1. 实现 proposal/revise/evaluate/approve/quarantine/promote/rollback。
2. generation immutable、hash-bound、ownership-bound。
3. 默认 propose；自动 Reviewer 只有有界 evidence。
4. 建 correction/repeated-success/recovery 信号。
5. 接 scanner、policy、paired eval、human gate。

Gate：Candidate 不能旁路成为 Capability；stale target 不可覆盖。
Push：segment/S15-evolution-workshop。

## S16：Code Capsule

步骤：

1. 定义 typed I/O、permission、runtime、resource budget。
2. 建 WASI/强隔离执行后端。
3. 生成 → scan → lock/SBOM → sandbox test → capability diff。
4. Eval、Review、signed digest、Shadow/Canary。

## 6. 每段执行时的节奏

### Day 0：读取与确认

- fetch、读 Continuity Pack、运行恢复测试；
- 输出本段 Acceptance、风险和预计文件；
- 不立即重构范围外代码。

### 中间 checkpoint

- 每完成一个可独立验证的子目标更新 STATE；
- 额度紧张或上下文变长时做 WIP commit + push；
- WIP 不进入 main。

### Gate Day

- 完整测试和安全检查；
- 更新 Evidence/Handoff/ADR/Traceability；
- commit、push、验证远端 SHA；
- CI/Review 未完成时状态为 AwaitingCI/AwaitingReview。

### 下一段

- 合入 main 后从最新 origin/main 开新分支；
- 新模型先重放快速测试；
- 不把前一段未关闭的问题静默带入下一段。

## 7. 下一步：只执行 S00

不要直接开始 S01-S24。下一次执行只需要：

1. 用户给出正式远程仓库 URL，或确认要新建哪个 owner/name/visibility。
2. 确认现有 docs 是否作为首个 commit 导入。
3. 确认 main 分支策略和是否用 GitHub/GitLab/Gitee。
4. 完成 S00、push、验证远端 SHA。
5. 用户确认 S00 Gate 后再开始 S01。

这就是“慢慢来”的控制点：任何时候都可以换大模型，但不能跳过事实、验收、交接和远程备份。
